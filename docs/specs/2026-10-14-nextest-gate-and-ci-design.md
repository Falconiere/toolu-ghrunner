# Run the test suite with cargo-nextest in the gate and CI — Design

**Date:** 2026-10-14   **Status:** Approved   **Author:** epic worker (#118)   **Topic:** replace `cargo test --workspace` with `cargo nextest run --workspace` + a separate doctest step in `tools/check.sh`, `ci.yml` (ubuntu and macOS) and `release.yml`

## Problem

`cargo test --workspace` runs 140 test harnesses one after another. Measured
locally before the change: 5m25s wall, 1438 passed (1437 tests + 1 doctest),
72 ignored. `cargo nextest run --workspace` on the same tree: 2m37s wall,
1437 passed, 72 skipped. bacon already uses nextest and `.config/nextest.toml`
exists, but the gate and CI do not. The gate must stay one command that CI
mirrors step for step (AGENTS.md).

## Non-Goals

1. No change to which tests exist, and no change to `--ignored` lanes
   (Docker/live) — those stay on `cargo test`.
2. No nextest profile tuning (retries, per-test timeouts, test groups).
3. No change to #108/#109 test-target layout.
4. No source-build of nextest in CI.

## Architecture

The test step becomes two commands, run in this order everywhere:

1. `cargo nextest run --workspace`
2. `cargo test --workspace --doc` (nextest does not run doctests)

nextest is installed in CI with `taiki-e/install-action` (`tool: cargo-nextest`,
prebuilt binary), placed after the Rust toolchain step. The same pair appears in
`tools/check.sh` `_check_rust`, `ci.yml` `ci` and `ci-macos`, and `release.yml`
`verify`. The workflow-shape tests (`ci_workflow_test.sh`,
`check_script_test.sh`) pin the pair so the mirror cannot drift.
Process-per-test also isolates the tests that mutate process env or install the
global tracing subscriber (#108); the existing `process_env` targets remain
valid and are not touched.

## Interfaces / Schema

- `tools/check.sh all` final step: `cargo nextest run --workspace` then
  `cargo test --workspace --doc`. `_usage` lists `cargo-nextest` as a
  requirement.
- Workflow steps: `Install cargo-nextest` (`taiki-e/install-action@v2`,
  `tool: cargo-nextest`), `Test` (`cargo nextest run --workspace`),
  `Doctests` (`cargo test --workspace --doc`).

## Failure modes and edge cases

- `cargo-nextest` missing locally: `_check_rust` fails with a clear message
  naming the install command, rather than cargo's generic "no such command".
- A failing test fails the nextest step (non-zero exit), as before.
- Ignored tests: nextest skips them by default like `cargo test`; the 72
  ignored count must match. The Docker `--ignored` CI steps are unchanged.
- A test that re-runs its own binary with `--exact` (AGENTS.md note) is
  unaffected: nextest runs each test as `<bin> <name> --exact --nocapture`
  semantics and the full suite passes (AC-2).

## Acceptance criteria

- **AC-1:** `tools/check.sh`, `ci.yml` (`ci`, `ci-macos`) and `release.yml`
  (`verify`) each run `cargo nextest run --workspace` followed by
  `cargo test --workspace --doc`, and CI installs nextest via
  `taiki-e/install-action`; `ci_workflow_test.sh` and `check_script_test.sh`
  assert this and pass, and fail on a mutated workflow that lacks it.
- **AC-2:** nextest executes the same number of tests as `cargo test` did:
  1437 tests (+72 ignored/skipped) plus 1 doctest = 1438 passed.
- **AC-3:** The PR records before/after Test-step times on both CI jobs.
- **AC-4:** `./tools/check.sh all` passes.
- **AC-5:** README/AGENTS.md describe the new gate and require
  `cargo-nextest`.
